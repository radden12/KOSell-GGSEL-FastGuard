# Установка чистого GGSEL Plugin Host на Bothost

## 1. Создайте Telegram-бота

Откройте `@BotFather`, отправьте `/newbot`, задайте название и username. Скопируйте токен.

## 2. Узнайте Telegram ID владельца

Получите свой числовой Telegram ID через `@userinfobot`.

## 3. Создайте GitHub-репозиторий

Создайте пустой приватный репозиторий. Через `Add file → Upload files` загрузите всё содержимое папки проекта. В корне репозитория должны находиться:

- `run.py`
- `main.py`
- `requirements.txt`
- `ggsel_bot/`
- `GGSelAPI/`
- `plugins/`

## 4. Подключите репозиторий к Bothost

Для приватного GitHub-репозитория используйте HTTPS-доступ и Personal Access Token. После подключения выберите ветку `main`.

Главный файл запуска:

`run.py`

## 5. Добавьте переменные окружения

```env
BOT_TOKEN=токен_нового_telegram_бота
OWNER_TELEGRAM_ID=ваш_telegram_id
GGSEL_API_KEY=api_ключ_ggsel
GGSEL_SELLER_ID=email_или_seller_id
DATA_DIR=/app/data
POLL_INTERVAL=6
LOG_LEVEL=INFO
```

Значения вводятся без кавычек.

## 6. Запустите бот

Выполните сборку и запуск. Откройте Telegram-бота и отправьте `/start`.

Чистая главная панель сначала содержит только кнопку `Управление плагинами`.

## 7. Установите плагин

Откройте:

`Управление плагинами → Добавить или обновить плагин`

Отправьте:

- `.py`, когда плагин состоит из одного файла;
- `.zip`, когда вместе с плагином нужны изображения, JSON-файлы или другие ресурсы.

После проверки бот сохранит файлы в `/app/data/plugins` и перезапустится. На главной панели автоматически появится отдельная кнопка плагина.

## 8. Обновление плагина

Повторно отправьте файл с тем же именем. Новый файл заменит старый, а конфиги в `/app/data/configs` сохранятся.

## 9. Удаление

Откройте `Управление плагинами`, выберите плагин и нажмите `Удалить плагин`. Конфигурационные файлы автоматически не стираются, чтобы случайно не потерять связки и историю.

## Хранилище Bothost

Постоянные данные:

- `/app/data/plugins` — загруженные плагины и ресурсы;
- `/app/data/configs` — настройки и связки;
- `/app/data/state.json` — обработанные заказы и сообщения;
- `/app/data/products` — файлы автовыдачи для совместимых плагинов.
